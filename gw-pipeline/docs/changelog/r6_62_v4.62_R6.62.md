## 本次改动（最小可行修复）

### 1. 在 gw-backend 内部 commit R6.62（commit 6066f4a）

**保留 working-tree 的 2 个修改 + 给 Java 工具链一个明确的家**：

| 文件 | 改动 | 影响 |
|------|------|------|
| `Jenkinsfile_k8s` | maven:3.8.2-openjdk-8 → maven:3.9-eclipse-temurin-21 | Spring Boot 3.x 需要 Java 17+，8 已低于最小值 |
| `settings.xml` (NEW) | tiered Maven mirror fallback | 中国网络环境下 Maven 依赖下载间歇性失败的根因 |

**settings.xml 设计**：
```xml
<mirrors>
  <!-- Tier 1: Maven Central 直接 (最快时) -->
  <mirror><id>central</id><mirrorOf>central</mirrorOf>
    <url>https://repo.maven.apache.org/maven2</url></mirror>
  <!-- Tier 2: Tencent 镜像 (国内低延迟) -->
  <mirror><id>tencent</id><mirrorOf>central</mirrorOf>
    <url>https://mirrors.cloud.tencent.com/nexus/repository/maven-public/</url></mirror>
  <!-- Tier 3: Huawei 镜像 (兜底) -->
  <mirror><id>huawei</id><mirrorOf>central</mirrorOf>
    <url>https://repo.huaweicloud.com/repository/maven/</url></mirror>
</mirrors>
```

Maven 按声明顺序解析 mirror，第一个可达的胜出。

### 2. 在 gw-platform 主仓 commit R6.62 .gitignore（commit 1d84523）

**只动一行 `.gitignore`**：
```
+ # R6.62: preserve nested gw-backend .git (it has its own history, R6.62+ commits there)
+ gw-backend/.git/
```

**为什么这样**:
- git **refuses** to `git add` individual files from a directory containing a nested `.git`（submodule-like safety）。
- 这条规则告诉 git「跳过 `gw-backend/.git`」（保留嵌套 repo 的独立性）。
- Java 源文件继续由 gw-backend 自己的 git history 追踪（master @ `6066f4a`）。

## 留待 R6.63+

### Option B: git subtree merge（推荐）

```bash
# Move gw-backend aside, then subtree merge
mv /d/AliCPT/gw-backend /tmp/gw-backend-original
cd /d/AliCPT
git subtree add --prefix=gw-backend /tmp/gw-backend-original master --squash

# Now gw-backend/ is tracked in monorepo with merged history
# (ecc4e36 + f63adaf + 85351b1 + fa13364 + 6066f4a)
```

**优点**:
- gw-backend 像 gw-frontend/gw-pipeline 一样正式进 monorepo
- 主仓 + 子仓历史统一，`git log gw-backend/` 直接看
- 未来 R6.63+ Java 改动直接 commit 到主仓即可

**缺点**:
- 一次性 destructive：嵌套 `.git` 删除（但历史已合并）
- 大合并（5 commits squash 后是一笔 merge commit）

### Option C: 保留 gw-backend 独立 + 主仓加 gitlink pointer（次选）

```bash
cd /d/AliCPT
git rm --cached gw-backend/  # remove any tracked
echo "gw-backend submodule https://github.com/NOBEL-Pxx/gw-backend.git 6066f4a9195e979dcd284be6580eecd9446075fc" > .gitmodules
git add .gitmodules
git submodule add https://github.com/NOBEL-Pxx/gw-backend.git gw-backend
```

**优点**:
- 真正的 submodule 语义
- gw-backend 可以推到独立 GitHub repo

**缺点**:
- 需要 PXX 手动 push gw-backend 历史到 GitHub
- CI 需要 clone 两个仓库（git submodule update --init）

### Option D: 不动，留 R6.62 现状（极简）

gw-backend 继续作为 sibling 目录独立维护，主仓只通过 changelog awareness。
未来 Java 改动直接 `cd gw-backend && git commit`。

**优点**: 零风险，零迁移成本
**缺点**: 主仓无 git 可见性，依赖人工 awareness
