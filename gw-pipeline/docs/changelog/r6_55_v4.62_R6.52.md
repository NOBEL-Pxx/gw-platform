## #1 Audit 搜索高亮 (match_field + match_offset)

### 实现 (observability.py)
```python
# R6.52 #1: case-insensitive highlight
q_lower = q.lower()
for r in rows:
    d = dict(r)
    match_field = None
    match_offset = -1
    for field in (family, action, actor, before_json, after_json):
        val = d.get(field)
        if val is None: continue
        if field in (before_json, after_json) and isinstance(val, (dict, list)):
            val = _json.dumps(val, ensure_ascii=False)
        if not isinstance(val, str): continue
        idx = val.lower().find(q_lower)
        if idx >= 0:
            match_field = field
            match_offset = idx
            break
    d['match_field'] = match_field
    d['match_offset'] = match_offset
```

附带修复: pre-existing bug - 5 个 LIKE 占位符无 params 绑定 (params: List[Any] = [needle]*5)。

## #5 Batch verify 并行 (ThreadPoolExecutor)

### 实现 (routes_v450.py)
```python
from concurrent.futures import ThreadPoolExecutor, as_completed
max_workers = int(os.environ.get(BATCH_VERIFY_WORKERS, 8))
if len(hashes) <= 4:
    # 小批量: 顺序
    for h in hashes: r = _verify_one(h)
else:
    # 大批量: 并行
    with ThreadPoolExecutor(max_workers=min(max_workers, len(hashes))) as ex:
        futures = {ex.submit(_verify_one, h): h for h in hashes}
        for fut in as_completed(futures): r = fut.result()
```

附带: batch verify 报告 xmp_present (来自 #4 的 XMP packet 字段)。

## R6.52 hotfix (post-deploy)

**commit c182306** — zjlab 部署后发现 UnboundLocalError

### 问题
zjlab gw-pipeline 容器首次 sync 后 `sign-pkcs7` 返回 500:
```
UnboundLocalError: cannot access local variable 'xmp_packet' where it is not associated with a value
```
根因: `xmp_packet = ""` 初始化在 `try: from cryptography ...` 之内,cryptography 缺失时整个 try 块跳过,变量未绑定。

### 修复
```python
# 移出 try 块:
xmp_packet = ""
xmp_document_id = ""
try:
    from cryptography.hazmat.primitives import hashes, serialization
    # ... 其余逻辑
```

### 第二个问题
zjlab 容器镜像未含 `cryptography` + `PyMuPDF` (sync-to-zjlab.py 只 docker cp 源码 + restart,不重建镜像)。

**手动修复**:
```bash
docker exec gw-pipeline pip install --no-cache-dir cryptography PyMuPDF
# 成功安装 cryptography 50.0.1 + PyMuPDF 1.28.2
```

**永久修复** (已实现, sync-to-zjlab.py v4.38 → v4.39, 2026-09-04):
`scripts/sync-to-zjlab.py` 现在自动检测 `gw-pipeline/requirements.txt` 本地 vs 远程的 SHA256,不同则触发 `docker compose build --no-cache gw-pipeline` + `up -d --force-recreate --no-deps`。详见 STATE_SNAPSHOT §45.11。

## 运维侧:auto-rebuild 永久修复 (2026-09-04 续)

为消除 R6.52 #4 部署时的 `UnboundLocalError` 反复发生 + `cryptography` 漏装,`scripts/sync-to-zjlab.py` 升级到 v4.39:

### 新增功能
1. `_sha256_file(path)` — 本地文件 SHA256
2. `_remote_sha256(tg, path)` — 远程文件 SHA256 (exec sha256sum)
3. `_pipeline_needs_rebuild(tg)` — diff 检测 → 返回 (changed, local_sha[:12], remote_sha[:12])
4. `_rebuild_pipeline_remote(tg)` — 触发 `docker compose build --no-cache gw-pipeline` + `up -d --force-recreate --no-deps`
5. `sync_pipeline()` 在上传 .py 之前先调用上述 diff 检测 → 必要时 rebuild
6. 上传循环同时发送 `requirements.txt` + `Dockerfile` (不只 .py)

### Banner 升级
`[pipeline-rebuild] Building gw-pipeline image on zjlab (~40-180s)...` → 透明输出 rebuild 过程
