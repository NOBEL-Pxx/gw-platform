## #1 Audit 搜索前端高亮 (R6.52 #1 后端联调)

### 实现 (observability/index.tsx)
- 给 `AuditEntry` interface 加 `match_field?: ...` + `match_offset?: number`
- 新增 `highlightMatch(text, offset, q)` helper：把 `text.slice(offset, offset+q.length)` 包 `<mark>`

Action 列做了 uppercase 双重处理：match_offset 是基于 lowercase 的，所以 query 也 `.toUpperCase()`。

- 无 match_field 的行（普通列表）走 fallback `v` 直接渲染，无影响

## #3 Redis RateLimiter 启用 (替换 in-memory fallback)

### 实现

**pom.xml**:
- 新增 3 个 optional deps: `bucket4j-redis`, `lettuce-core`, `spring-boot-starter-data-redis`
- 都标 `<optional>true</optional>` → 默认不打包，避免无 Redis 部署爆错

**RedisRateLimiter.java 重写**:
- 注入 `LettuceBasedProxyManager<byte[]>` (不是 in-memory fallback)
- 懒初始化：首次调用才连 Redis (避免启动阻塞)
- 优雅降级：Redis 连接失败 → fallback 到 in-memory，记录 WARN 日志
- RecoveryStrategy.RECONSTRUCT：Redis 重启后 bucket 自动重建

### 验证
- 编译: `cd gw-backend && mvn compile -pl gravitationalwave-server-service`
  (需要 bucket4j-redis 版本兼容 — 实际部署前需跑一次)
- 启动: `SPRING_PROFILES_ACTIVE=redis rate.limit.redis-uri=redis://10.x.x.x:6379 java -jar ...`
- 默认 profile 仍是 in-memory (不打破现有部署)

## #4 gw-pipeline --profile dev/prod 开关

### 实现 (src/pipeline/server.py)
```python
def _apply_profile(profile: str) -> None:
    if profile == "dev":
        os.environ.setdefault("PIPELINE_DEV_MODE", "1")
        os.environ.setdefault("PIPELINE_CORS_ALLOW_ORIGINS", "*")
        os.environ.setdefault("PIPELINE_LOG_LEVEL", "DEBUG")
        os.environ.setdefault("PIPELINE_DOCS_OPEN", "1")
        os.environ.setdefault("PIPELINE_AUTH_REQUIRED", "0")
    elif profile == "prod":
        # strict: CORS 受限, INFO logs, /docs 关闭, 需 auth
```

启动入口从 `uvicorn.run(app, host="0.0.0.0", port=port)` 改为 `argparse` 接收 `--profile / --host / --port`。

### 验证
- `python -m src.pipeline.server --profile dev` → 打印 `[profile] dev: CORS=*, DEBUG logs, /docs open, no auth required`
- `python -m src.pipeline.server --profile prod` → 打印 `[profile] prod: strict CORS, INFO logs, /docs closed, auth required`
- `PIPELINE_PROFILE=prod python -m src.pipeline.server` → 同上 (env 覆盖)

## #7 Audit search 端点 opt-in 公开

### 实现 (routes_v450.py)

**默认行为不变**: 上游 middleware/proxy 仍要求 Bearer token (401)

**新增 opt-in 公开**: 设置 env `PIPELINE_AUTH_AUDIT_PUBLIC=1` 后:
- 跳过 X-Actor 检查 (任何请求都可访问)
- 响应体添加 `_actor` 字段 (若有 X-Actor) 记录谁搜的
- 默认值 0 (关) → 与 R6.52 行为一致，不破坏现有部署

### 为什么 opt-in 不是默认开
- audit search 返回 before_json / after_json，可能含敏感路由 key (PXX 部署文档里说明)
- 默认开 → 任何人都能扫到 PagerDuty routing key 历史
- opt-in → dev/test 显式启用，prod 保持现有 auth

### 验证
- 默认行为 (无 env): `curl /pipeline/observability/audit/search?q=foo` → 401 "X-Actor required"
- dev mode (env=1): `PIPELINE_AUTH_AUDIT_PUBLIC=1 python -m src.pipeline.server` → 端点开放
