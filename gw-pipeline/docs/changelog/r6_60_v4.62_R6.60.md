R6.59+ zjlab Redis 部署成功后发现一个隐蔽问题：

> zjlab 远程 `/home/zjlab/gravitationalwave-v4.31/` 目录里**实际跑着 5 个 compose 文件**，
> 包括 `docker-compose.zjlab.yml` / `docker-compose.prod.yml` / `docker-compose.monitoring.yml` /

这意味着任何 `git pull`/回滚/同步都会**丢失生产配置**。

## 本次提交内容

### 1. `docker-compose.zjlab.yml` (v4.31, 73 行)
**唯一对内**生产覆盖配置：
- 端口收口：mongodb/elasticsearch/firefly/backend/pipeline/mcp 全部 `ports: []`，仅 gw-frontend 暴露 6001/6002
- 资源 limits：mongodb/ES/backend 各 4G 内存+4 CPU；pipeline 8G+8 CPU + 1× Tesla V100 GPU
- JAVA_OPTS: `-Xms1g -Xmx3g`
- `GW_EXCLUDE_GPL_MODELS=false`（内部科研使用，保留 GPL 模型）
- 前端构建 APP_RUN_ENV=prod（覆盖 dev 默认）

### 2. `docker-compose.prod.yml` (v4.16, 47 行)
通用生产覆盖（早期版本）：
- 端口收口（同样的策略）
- `rate.limit.capacity=30` / `refill-minutes=1`（prod 限流，比 dev 120 严格 4×）
- 注释保留 ES TLS + audit logging 钩子（参考 docs/es-auth-config-v4.16.md）

### 3. `docker-compose.monitoring.yml` (v4.37, 80 行)
可选监控栈（独立启用）：
- Prometheus 2.51.0（端口 9090，scrapes pipeline:8200/metrics 每 15s）
- Grafana 10.4.0（端口 3000，预置 AI dashboard）
- 加固：read_only/no-new-privileges/cap_drop ALL/user nobody
