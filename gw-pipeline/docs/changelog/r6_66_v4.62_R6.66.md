## 三大 deliverable

### R6.66.2 — Docker Compose v2.29.7 upgrade + nginx upstream fix

**问题**: 之前 compose v2.19.1 静默吞 `:mode=` suffix，R6.65 删了 read_only 后没恢复。
**根因**: gw-frontend official image `nginx:1.19.9-alpine` uses `USER nginx` (uid 101)，即使 tmpfs mode=1777，nginx user 仍无法 chown /var/cache/nginx away。

**修改**:
1. `/usr/local/bin/docker-compose` 升级到 v2.29.7 static binary
2. `gw-frontend` service: read_only + tmpfs 全部 REVERT（documented in compose comment as R6.66.2.a-d）
3. nginx `locations-common.conf`: upstream 改名 `gw-backend` → `divs-backend`（container_name = DNS alias；service name 仅在没 container_name 时生效）
4. 已部署到 zjlab: `python scripts/sync-to-zjlab.py frontend`

**留待 R6.67+**:
- Custom Dockerfile wraps nginx start with chown（or switch pid path to `/tmp/nginx.pid` which is already mode 1777）
- redis/es permission + port 9200 conflicts（manual infra）

### R6.66.3 — Mongo-backed audit (real write + health endpoint)

**问题**: 之前 `audit_mongo.py` 的 `_get_mongo()` 用 sync `AsyncIOMotorClient` ctor — motor 是 lazy connect，client 构造成功不代表 Mongo 真可达。
**修复**:
1. `_get_mongo_async()`: async lazy init + serverSelection ping 验证
2. `_verify_mongo(client)`: 实际发 ping，记录 `_last_ping_ts` + `_last_ping_err`
3. `is_enabled()` / `get_health()`: env toggle + state snapshot
4. `_AUDIT_MONGO_ENABLED` env flag: 默认 true，可完全 opt-out
5. `write_audit_entry`: 改用 `_get_mongo_async`，写失败时 mark `_mongo_available=False` 强制下次 re-ping
6. **NEW endpoint**: `GET /pipeline/admin/audit/health` returns `get_health()` JSON

**文件**:
- `gw-pipeline/src/pipeline/audit_mongo.py` — async ping verification
- `gw-pipeline/src/pipeline/routes_v437.py` — `/pipeline/admin/audit/health` 路由
