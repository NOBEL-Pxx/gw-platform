## 背景

2MASS/NVSS 等 HiPS survey 首次访问有 **~1.5s 延迟**（DNS + TLS 握手 + 跨网延迟）。
R6.49 引入了 sessionStorage 60s 缓存，但：
- sessionStorage **不跨 tab 共享** → 新 tab 又得重新探测
- 60s TTL 太短 → 用户切换 survey 后过期
- **没有 preconnect** → 浏览器无法提前建立 TCP/TLS 连接

## 本次改动（hips.ts +1437 chars）

### 1. localStorage 24h TTL（跨持久化）
```ts
const RESOLVE_TTL_MS = 24 * 60 * 60 * 1000  // was 60_000

// 新增：版本化 key 前缀 (gw-hips-v1:)，未来 schema 迁移可 bump 到 v2
// 新增：readLsCache() — 自动检测 24h 过期并删除
// 新增：writeLsCache() — quota exceeded 静默失败回退到 memCache
```

**所有 cache.set 路径都同步写入 localStorage**：
- 后端 resolve 成功 → memCache + localStorage
- fallback (alasky.cds) → memCache + localStorage

### 2. preconnect 预热（DNS+TLS 提前）
```ts
const HIPS_ENDPOINTS = [
  'https://alasky.cds.unistra.fr',
  'https://aladin.u-strasbg.fr',
  'https://archives.esac.esa.int',
]

export function preconnectHipsEndpoints(): void {
  // Idempotent — 浏览器去重 hint per origin
  HIPS_ENDPOINTS.forEach(href => {
    const link = document.createElement('link')
    link.rel = 'preconnect'
    link.href = href
    link.crossOrigin = 'anonymous'
    document.head.appendChild(link)
  })
}
```

**buildHipsUrl 每次调用都触发 preconnect（首次后无开销）** → 浏览器立刻开始 DNS+TLS，后续 fetch 走 0-RTT。

### 3. clearHipsCache 升级
原来只清 memCache。R6.61.a 也清 localStorage 的 `gw-hips-v1:*` 键。

## ⚠️ 注意事项

- **localStorage quota**: ~5-10MB per origin。HiPS cache 每 entry ~50 bytes，
  即使 10000 次探测也只占 0.5MB，安全。
- **CDN 端点变更**: 如果 CDS 永久下线某 endpoint，clearHipsCache() + reload 触发新探测。
- **CSP 影响**: preconnect link 不影响 CSP（不需要 wasm-unsafe-eval）。
