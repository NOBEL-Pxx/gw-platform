## 三大 sync 修复

### Fix 1: Container-aware SHA detector

```python
def _pipeline_needs_source_rebuild(tg, sftp):
    """对比 LOCAL vs CONTAINER (不是 remote host path)"""
    cmd = 'docker exec gw-pipeline sha256sum /app/src/pipeline/*.py /app/src/pipeline/agent/*.py 2>/dev/null'
    si, so, se = tg.exec_command(cmd, timeout=30)
    out = so.read().decode()
    for line in out.splitlines():
        sha, p_full = line.split()[:2]
        container_files[os.path.basename(p_full)] = sha
    changed = sum(1 for k, v in local_files.items() if container_files.get(k) != v)
    return (changed > 0, changed, len(container_files))
```

**为什么不能读 host path**: zjlab host `/home/zjlab/gravitationalwave-v4.31/gw-pipeline/src/pipeline/*.py` 可能 stale (rebuild skip 后没更新)。`docker exec gw-pipeline sha256sum` 永远是正在运行的版本。

### Fix 2: Upload source BEFORE rebuild

| 旧顺序 | 新顺序 |
|---|---|
| 1. rebuild (OLD source) | 1. upload new source |
| 2. upload new source | 2. rebuild (FRESH source) |
| 3. docker cp -> **FAIL** (read-only) | 3. recreate container |
| 4. restart | |

**根因**: R6.60+ security best practice 把 container rootfs 标 `read-only: true`，`docker cp` 失败。唯一部署新代码的方式是 image rebuild。

### Fix 3: All change detection BEFORE upload

旧流程先 upload 再 detect SHA -> 永远 "no changes" (本地刚被上传覆盖)。  
新流程先 detect -> 决策 -> 再 upload -> 然后 conditional rebuild。

### Fix 4: Pure-source change detection (免 trigger)

R6.52 #1 改动是纯 source change，没动 requirements.txt。  
旧逻辑只看 requirements.txt SHA -> 不会触发 rebuild -> 需要手动 `touch requirements.txt` 加注释触发。  
新逻辑直接对比 source SHA -> 自动触发，无需 trigger hack。
