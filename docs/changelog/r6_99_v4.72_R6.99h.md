## Summary

R6.99-C caches HiPS tiles in the browser Service Worker (repeat visits instant). R6.99-H adds a backend proxy with disk cache so:
1. **Cold visits** still pay 1.5s/tile CDS cost, BUT only ONCE — backend caches for all subsequent users.
2. **Backend serves all users** — 10 researchers × 57 tiles = 570 wasted CDS fetches/observation now reduced to 57 (one fetch serves all).

**Architecture:** New endpoint `/pipeline/hips-tile/{z}/{x}/{y}?survey=...&endpoint=...` in `gw-pipeline`. Browser fetches via backend proxy. Backend checks `/var/cache/gw-hips/<SHA256[:16]>.jpg` — HIT returns from disk (<50ms), MISS fetches from CDS (~1.5s), caches, returns. 50 GB / 200k tile LRU cap, 30-day TTL.

## Endpoint spec

`GET /pipeline/hips-tile/{z}/{x}/{y}?survey=<id>&endpoint=<host>`

| Param | Type | Constraint |
|-------|------|------------|
| `z` (path) | int | `[0, 19]` |
| `x` (path) | int | `[0, 2^z - 1]` |
| `y` (path) | int | `[0, 2^z - 1]` |
| `survey` (query) | string | `^[A-Za-z0-9_/-]{3,64}$` (regex validated) |
| `endpoint` (query) | string | 7-host allowlist only |
| `If-None-Match` (header) | string | optional, for ETag 304 |

**Responses:**
- `200 OK` + tile bytes (`image/jpeg`/`image/png`) — HIT or MISS
- `304 Not Modified` — `If-None-Match` matches ETag
- `400 Bad Request` — endpoint not in allowlist
- `404 Not Found` — CDS returns 404 (invalid tile coords)
- `413 Payload Too Large` — tile > 1 MB
- `422 Unprocessable Entity` — FastAPI query/path validation rejection (e.g. z=99, survey=../../etc/passwd)
- `502 Bad Gateway` — CDS unreachable after 2 retries

**Headers:**
- `ETag: <sha256[:16]>` — client cache
- `Cache-Control: public, max-age=86400, immutable` — CDN-level
- `X-Hips-Cache: HIT|MISS` — observability

## Cache strategy

| Aspect | Value |
|--------|-------|
| Cache dir | `/var/cache/gw-hips/` (bind-mount in compose, `./docker-data/hips_tile_cache`) |
| File format | `{key}.jpg` (or `.png` per upstream Content-Type) |
| Key | `SHA256(survey:z:x:y)[:16]` — NEVER user input directly |
| Max size | 50 GB OR 200k tiles (whichever first) |
| TTL | 30 days (mtime-based LRU) |
| Eviction | LRU on access (`os.utime()` on read); O(n log n) sort by mtime |
| ETag | SHA256 of file bytes |
| Lock | Per-key `fcntl.flock()` (1 KB write lock file) — prevents thundering herd on cold tile |

## 3-perspective review (per [[parallel-review-after-batch]])

Dispatched correctness + perf + security agents in parallel BEFORE commit. All findings applied:

### Security (2 HIGH must-fix + 3 MEDIUM + 1 LOW)
- ✅ **HIGH-1 SSRF via redirect** — set `follow_redirects=False` on httpx (HiPS URLs don't redirect; prevents attacker-controlled redirect to internal services)
- ✅ **HIGH-2 OOM via streaming** — use `client.stream()` + chunked `aiter_bytes()` with early 1MB break (prevents loading 5MB+ bodies into memory)
- ✅ **MEDIUM-1 auth posture** — added `/pipeline/hips-tile` to `_PUBLIC_PREFIXES` in `rbac.py:71` (matches existing pattern: `hips-thumb`, `hips-float`, `hips-stats`)
- ✅ **MEDIUM-2 exception leak** — generic 502 messages (`"CDS unreachable"`, `"CDS error"`) instead of leaking `e.__class__.__name__`
- ✅ **LOW-3 allowlist dup** — replaced duplicate `alaskybis.unistra.fr` with `alasky.u-strasbg.fr` (aladin legacy)

### Perf (5 HIGH + 6 MEDIUM + 4 LOW)
- ✅ **HIGH-4 eviction off hot path** — debounced 5min on `_hips_tile_evict_if_needed` (saves 200-1000ms p99)
- ✅ **HIGH-5 httpx client reuse** — module-level lazy `httpx.AsyncClient` (saves 100-300ms per cold fetch via TCP+TLS handshake reuse)
- ✅ **MEDIUM-5 concurrency limit** — `asyncio.Semaphore(8)` on CDS fetches (prevents DoS cascade)
- ✅ **LOW-2 Pydantic v2** — `regex=` → `pattern=` on `Query(..., pattern=HIPS_TILE_SURVEY_REGEX)`

### Correctness (1 HIGH + 2 MEDIUM + 9 LOW)
- ✅ **H1 sync script bind-mount** — replaced `docker restart gw-pipeline` with `docker compose up -d --force-recreate --no-deps gw-pipeline` (restart reuses existing container config and does NOT pick up new bind-mount)
- ✅ **L1 lock file pollution** — unlink empty `.lock` file in `finally` (cache dir doesn't fill with stale `.lock` stubs)
- ✅ **L2 size-before-mtime** — `cache_path.stat().st_size` check FIRST on HIT path + `unlink()` on 413 (prevents oversized cached files becoming immortal under LRU)
- ✅ **L5 frontend regex** — tightened from `[a-z]+$` to `(?:\.jpg|\.png|\.webp)$` + anchored start `^` (prevents matching `.preview.jpg`)
- ✅ **L8 evict unlink error** — re-insert victim on `OSError` (don't shrink `files` list on failure → loop keeps trying)

### Deferred (out of scope for v1)
- **M1 hardcoded `.jpg`** — standard HiPS tile pattern is always `.jpg`; PNG/WebP are allsky overlays (separate HiPS object type). Adding `ext` parameter defers to R6.99-H.b
- **M2 endpoint allowlist drift** — frontend preconnects to `aladin.u-strasbg.fr` + `archives.esac.esa.int`; not in backend allowlist. Currently no `R6.99-H` user-visible impact (frontend falls back to direct CDS). Document in [[gw-r627f-hips-backend-proxy]] cross-ref.

## Security (4 iron rules + 1 added by review)

## Security (4 iron rules + 1 added by review)

1. **R6.99-H-allowlist-only**: `endpoint` MUST match hardcoded 7-host allowlist:
   - `alasky.cds.unistra.fr`, `alaskybis.cds.unistra.fr`, `alasky.unistra.fr`, `alaskybis.unistra.fr`
   - `hips.china-vo.org`, `irsa.ipac.caltech.edu`, `skies.esac.esa.int`
   - No user-controlled SSRF.
2. **R6.99-H-cache-key-via-sha256**: cache filename MUST be SHA256[:16] of `(survey:z:x:y)`. Never use user input directly (path traversal defense).
3. **R6.99-H-thundering-herd-lock**: per-key `fcntl.flock()` prevents N concurrent fetches of same cold tile. Falls back to no-op on Windows (cross-platform compat).
4. **R6.99-H-1mb-response-cap**: response body capped at 1 MB (mirrors R6.98-C streaming cap iron rule). Both cache hit + cache miss paths enforce.

**Additional defenses:**
- `survey` param regex `^[A-Za-z0-9_/-]{3,64}$` blocks `.`, `/../`, etc. via FastAPI's standard query validation.
- `z/x/y` range validated via `PathParam(ge=0, le=19)` + explicit `x >= 2**z` check.
- httpx default TLS verification enabled (no way to disable).
- 502 errors return generic message (`CDS unreachable`/`CDS error: <type>`) — no upstream URL leaked.

## Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Cache fills disk | LRU at 50 GB ceiling; future Prometheus alert (Phase 3) |
| CDS endpoint changes | Hardcoded allowlist + validated URLs; periodic endpoint health check (manual) |
| Cache poisoning | ETag = SHA256(bytes); upstream changes → new ETag → miss (cache invalidates naturally) |
| Frontend regression | Frontend falls back to direct CDS if proxy fails (graceful degradation) |
| Local dev (Windows) | fcntl no-op fallback; thundering-herd protection unavailable locally (acceptable) |
