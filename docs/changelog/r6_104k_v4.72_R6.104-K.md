## Summary

Both image viewers (Multi-band Observation + FITS Viewer) now expose the same
AladinLite-v3-style display control surface. One TypeScript interface —
`DisplayParams` — describes the whole display pipeline, and one React panel
(`DisplayControls`) renders it for both consumers. The backend gained the
stretches and post-stretch coefficients the UI can now ask for.

## What changed

### `DisplayParams` is the SSOT

```ts
{ stretch, colormap, cutMode, minCut, maxCut,
  gamma, brightness, contrast, saturation }
```

Both `FireflyViewer` (FITS) and `MultiBandDataPanel` (multi-band) import it from
`@/components/DisplayControls/types`. Component-local copies of these fields are
forbidden (R6.104-K-A).

- **Stretch**: `linear`, `sqrt`, `log`, `asinh`, `pow2` (NEW), `equalization` (NEW)
- **Colormap**: 10 LUTs (`viridis`, `plasma`, `inferno`, `magma`, `cividis`,
  `cubehelix`, `parula`, `grayscale`, `rainbow`, `native`)
- **Cuts**: dual-mode — `percent` (-1..100, -1 = Auto) OR `absolute` (0..65535)
- **Post-stretch coefficients**: `gamma` (0.3–3.0), `brightness` (-0.5..+0.5),
  `contrast` (0.5–2.0), `saturation` (0..2.0)
- **Auto button** — percentile clip from the visible histogram
- **Histogram preview** — 256 bins with two draggable handles
- **Color palette grid** — 3×3 + 1 with inline canvas LUT swatches

Multi-band additionally keeps **per-band** overrides: each band tile carries its
own `DisplayParams`, so H can be log/stretched while J stays asinh.

### Defaults = no noise on mount

- `HIPS_PROFILE` expanded **6 → 11** surveys (`2MASS-color`, `Gaia-DR3`,
  `NVSS-color`, `Planck-LFI`, `Planck-HFI` added).
- Unknown survey → `FALLBACK_DISPLAY_PARAMS` = **asinh + 3% / 99.7%**
  (concrete window, *not* the Auto sentinel — see R6.104-K-C).

### Cut-mode sentinel is a PAIR

"Let the renderer choose its own window" is `minCut === -1 && maxCut >= 100`,
detected as a pair by `isAutoWindow()`. `maxCut` 100 on its own is a legitimate
explicit request for "no top clipping" and is forwarded verbatim. This was a
real defect caught by the new test suite mid-implementation, not a design
preference: a single-value test silently collapsed `{minCut: 0, maxCut: 100}`
back to the survey default.

### Big image lazy-load

`LazyBigImage` renders a 30%-opacity placeholder + "Click to load" affordance
for the *active* big image (partial revert of R6.99-A). Non-active thumbnails
stay `loading=lazy` + `fetchPriority=auto`.

### Backend extensions

`/pipeline/hips-float` and `/pipeline/merge-rgb` accept 7 new params:
`stretch` (`pow2`/`equalization` added), `gamma`, `brightness`, `contrast`,
`saturation`, `cut_mode` (`percent`/`absolute`), `min_cut_abs`, `max_cut_abs`.
Coefficient order matches AladinLite v3 §10:
cut → stretch → colormap → reverse → gamma → brightness → contrast → saturation.
The `/pipeline/hips-float` percentile params are clamped to the ranges
`hips.py` declares (`min_cut_pct` 0–49, `max_cut_pct` 51–100) so an out-of-range
UI value degrades to the nearest legal window instead of returning HTTP 422.

Direct-CDS requests (`hips2fits`) validate `stretch` and reject the backend-only
values with HTTP 400, so `cdsStretchFor()` maps `pow2`/`equalization` → `linear`
on that path rather than failing.

## Iron rules (3 new)

- **R6.104-K-A** — `DisplayParams` is the SSOT for both viewers; no
  component-local copies.
- **R6.104-K-B** — Histogram preview is non-blocking: bars are
  `pointer-events: none`, only the two handles are `pointer-events: auto`, and
  the handles render **only** when `bins` exist. An image canvas is never
  read back synchronously on the main thread.
- **R6.104-K-C** — Unknown survey default = `asinh + 3% / 99.7%`, as a concrete
  window (the Auto sentinel would omit the params entirely and silently inherit
  the renderer default instead).
