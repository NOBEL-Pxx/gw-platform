## Summary

Both image viewers (Multi-band Observation + FITS Viewer) now expose the same
AladinLite-v3-style display control surface. One TypeScript interface --
`DisplayParams` -- describes the whole display pipeline, and one React panel
(`DisplayControls`) renders it for both consumers. The backend gained the
stretches and post-stretch coefficients the UI can now ask for.

## What changed

### `DisplayParams` is the SSOT

```ts
{ stretch, colormap, cutMode, minCut, maxCut,
  gamma, brightness, contrast, saturation }
```

Both `FireflyViewer` (FITS) and `MultiBandDataPanel` (multi-band) import it from
`@/components/DisplayControls/types`. Component-local copies of these fields are
forbidden (R6.104-K-A). Every write path funnels through `clampDisplayParams`;
the review closed the one control (`AdvancedSliders`) that bypassed it.

- **Stretch**: `linear`, `sqrt`, `log`, `asinh`, `pow2` (NEW), `equalization` (NEW)
- **Colormap**: 10 LUTs (`viridis`, `plasma`, `inferno`, `magma`, `cividis`,
  `cubehelix`, `parula`, `grayscale`, `rainbow`, `native`)
- **Cuts**: dual-mode -- `percent` (-1..100, -1 = Auto) OR `absolute` (0..65535)
- **Post-stretch coefficients**: `gamma` (0.3–3.0), `brightness` (-0.5..+0.5),
  `contrast` (0.5–2.0), `saturation` (0..2.0)
- **Color palette grid** -- 3×3 + 1 with inline canvas LUT swatches

Multi-band additionally keeps **per-band** overrides: each band tile carries its
own `DisplayParams`, so H can be log/stretched while J stays asinh.

### Implemented but not wired (corrected 2026-09-26)

An earlier revision of this file listed the Auto button and the histogram preview
as shipped features. They are **implemented and unit-tested but reachable by no
production consumer**, so a user cannot use them today:

- `DisplayControls` accepts `histogram: bins | null` (defaulting to `null`) and
  `onAutoStretch`. `Histogram.tsx` paints "Histogram unavailable" and returns
  early when `bins` is falsy, so the two draggable handles never mount.
- A grep for `histogram=` across `gw-frontend/src/pages` and
  `gw-frontend/src/components` (excluding `__tests__`) returns **nothing**.
- `FireflyViewer` passes `onAutoStretch` but not `histogram`, so the Auto button
  renders and is permanently `disabled={!histogram}` -- its handler is dead code.
- `MultiBandDataPanel` passes neither prop, so the Auto button is not rendered at
  all and the histogram canvas shows "Histogram unavailable".

Neither is broken; both are unwired. Fixing it means producing bins (a
synchronous canvas read-back is forbidden by R6.104-K-B, so the bins have to come
from the backend or an off-thread pass).

### Defaults = no noise on mount

- `HIPS_PROFILE` expanded **6 → 11** surveys (`2MASS-color`, `Gaia-DR3`,
  `NVSS-color`, `Planck-LFI`, `Planck-HFI` added).
- Unknown survey → `FALLBACK_DISPLAY_PARAMS` = **asinh + 3% / 99.7%**
  (concrete window, *not* the Auto sentinel -- see R6.104-K-C).

### Cut-mode sentinel is a PAIR

"Let the renderer choose its own window" is `minCut === -1 && maxCut >= 100`,
detected as a pair by `isAutoWindow()`. `maxCut` 100 on its own is a legitimate
explicit request for "no top clipping" and is forwarded verbatim. This was a
real defect caught by the new test suite mid-implementation, not a design
preference: a single-value test silently collapsed `{minCut: 0, maxCut: 100}`
back to the survey default.

### Big image lazy-load

The *active* big image is click-to-load (partial revert of R6.99-A): Aladin1's
`lazy` prop plus a 30%-opacity placeholder and a "Click to load" overlay. This is
**not** a `LazyBigImage` component -- an earlier revision of this file named one
that does not exist. Non-active thumbnails stay `loading=lazy` +
`fetchPriority=auto`.

Because the big `<img>` does not exist when the parent's `currentBand` effect
first runs, `useContrastDOM` remembers the last params per band and re-applies
them from `registerBig` -- a callback ref that fires when the element mounts.

### Backend extensions

`/pipeline/hips-float` and `/pipeline/merge-rgb` accept 7 new params:
`stretch` (`pow2`/`equalization` added), `gamma`, `brightness`, `contrast`,
`saturation`, `cut_mode` (`percent`/`absolute`), `min_cut_abs`, `max_cut_abs`.
Coefficient order matches AladinLite v3 §10:
cut → stretch → colormap → reverse → gamma → brightness → contrast → saturation.

The **frontend** clamps the percentile params to the ranges `hips.py` declares
(`min_cut_pct` 0-49, `max_cut_pct` 51-100) before sending, so a UI value outside
that range degrades to the nearest legal window rather than a 422. The backend
bounds are the contract; the frontend is what honours it.

Direct-CDS requests (`hips2fits`) validate `stretch` and reject the backend-only
values with HTTP 400, so `cdsStretchFor()` maps `pow2`/`equalization` → `linear`
on that path rather than failing.

**Named limit: gamma is inert on the standard path.** CSS `filter` has no gamma
primitive and no `<feColorMatrix>` pre-bake exists in this app, so `gamma` does
nothing on any path rendered through `useContrastDOM` (standard JPEG tiles and
thumbnails). It works only on the Hi-Q path, where the server bakes it. The
comment in `useContrastDOM.ts` that claimed otherwise has been corrected.

## Iron rules (3 new)

- **R6.104-K-A** -- `DisplayParams` is the SSOT for both viewers; no
  component-local copies. Every write funnels through `clampDisplayParams`.
- **R6.104-K-B** -- Histogram preview is non-blocking: bars are
  `pointer-events: none`, only the two handles are `pointer-events: auto`, and
  the handles render **only** when `bins` exist. An image canvas is never
  read back synchronously on the main thread.
- **R6.104-K-C** -- Unknown survey default = `asinh + 3% / 99.7%`, as a concrete
  window (the Auto sentinel would omit the params entirely and silently inherit
  the renderer default instead).

### Deploy infra fixes (required to ship)

The first deploy attempt failed silently. Three infra defects were found and
fixed, all committed and pushed:

1. **T5 mirror regression** - the T5 Dockerfile change added `-i
   pypi.tuna.tsinghua.edu.cn`, which returns **HTTP 403** from the zjlab server
   ("from versions: none" for every package, so the build fails). Switched to
   the Aliyun mirror (`mirrors.aliyun.com/pypi/simple`, HTTP 200 / 0.15s from
   zjlab); the pypi.org `--extra-index-url` fallback that followed then stalled
   the build at 0% CPU, so it was dropped. Commits `4e4edde`, `1f5ca41`.
2. **`sync-to-zjlab.py` cannot fail** - the build channel has a 600s timeout and
   `tail -12` buffers all output, so a slow/hung build leaves the log empty and
   the script proceeds to recreate from the **stale** image while printing
   `[DONE]`. This is the review's "deploy script cannot fail" finding, confirmed
   in production.
3. **Read-only rootfs** - `docker cp` is impossible (`ReadonlyRootfs = true`),
   so an image rebuild is the *only* backend deploy path; a hung build had to be
   killed (with user authorization) before the rebuild could proceed.
