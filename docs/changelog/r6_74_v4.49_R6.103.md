## Summary

R6.99 #4 proposed a 5→4 conf.d directory consolidation based on the assumption that
`nginx-shared/` and 3 files in `nginx-includes/` (csp-header.conf, hsts.conf,
security-headers.conf) were dead code. R6.103 attempted the migration; the 3-perspective
review (security + deploy + docs) caught that this assumption was WRONG:

`default.conf.template` (the file Dockerfile COPYs to `/etc/nginx/templates/` for envsubst
at container start) **actively INCLUDES all 5 files** at lines 47-51:

```nginx
include /etc/nginx/shared/server-common.conf;       # keepalive + client_max_body_size 50m + R6.37 sub_filter
include /etc/nginx/includes/hsts.conf;              # REQUIRED for HTTPS production
include /etc/nginx/includes/security-headers.conf;  # X-Frame-Options, X-Content-Type-Options, etc.
include /etc/nginx/includes/csp-header.conf;        # CSP enforcement
include /etc/nginx/shared/locations-common.conf;    # All 8 production location blocks
```

The implementation phase was correctly blocked by the safety classifier before any
file was deleted. The verify phase confirmed no files were changed.

## Lessons (R6.103)

1. **Always grep ALL *.conf + *.template + Dockerfile for include chains** before claiming
   dead code. `default.conf.template` was missed by my initial grep.
2. **CRITICAL security config (HSTS, CSP) lives in includes, not in nginx.conf** — easy
   to miss when scanning master config.
3. **A file that's COPIED via Dockerfile + bind-mounted + has active include statements
   is the OPPOSITE of dead code**. The 5 files have all three.
4. **3-perspective review saved production**. Single-perspective would have shipped the
   migration; the security lens alone caught HSTS, the deploy lens caught the include chain,
   the docs lens caught the stale references.
5. **"No-op closure" is a valid R6.x outcome**. The migration was correctly NOT done; documenting
   the false alarm + the corrected analysis is the deliverable.
