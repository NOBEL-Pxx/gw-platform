## Summary

R6.98 closes 4 deferred security/DoS hardening items from R6.95 → R6.97. Three of the four
(O-4 TLS pinning, O-10 DNS pinning, plus content-type validation) require Apache HttpClient 5
(Spring `RestTemplate` does not expose `SSLContext` or `DnsResolver`). The fourth (O-9
streaming cap) extends the existing R6.96 inbound pattern to outbound.

The migration touches 4 outbound-HTTP-using files: ImageCutoutDataSet (HIGH risk, china-vo.org),
LlmController (MEDIUM, api.deepseek.com), PipelineProxyController (LOW, gw-pipeline internal),
AuditService (LOW, gw-pipeline audit channel). All 4 are migrated from `RestTemplate` to
Spring's modern `RestClient` backed by a shared or dedicated `CloseableHttpClient` bean.

## Iron rules added (R6.98-A / B / C / D)

### R6.98-A — TLS pinning MANDATORY for outbound HTTPS to mutable-DNS third parties

Outbound HTTPS to third-party services (china-vo.org, api.deepseek.com, etc.) MUST go through
a pinned `CloseableHttpClient` built by `TlsPinningHttpClientFactory`. No ad-hoc
`new RestTemplate()` or default `HttpClients.createSystem()` for cross-network calls.

Pinning mechanism: custom `X509TrustManager` that post-filters by SPKI SHA-256 (RFC 7469 best
practice — pins the public key, not the cert, so cert rotation with same key pair is transparent).
V1 marker: `R6.98: TLS pinning active for {host} (cert SHA-256: {hex})` emitted at construction.

TOFU capture: pinned fingerprint is a `@Value` config (`{host}.api.pinned-cert-sha256`).
When unset, the bean falls back to the shared client with a clear log warning — dev mode
permitted; prod deploy forces ops to capture the cert on first run.

**Enforced for:** LlmController (R6.98-A) + ImageCutoutDataSet (R6.98-A).

### R6.98-B — Content-Type validation MANDATORY for binary format consumers

Response MUST have expected `Content-Type` header OR match magic-byte sniff before being
treated as that format. Rejects MIME-confusion attacks (e.g., HTML response claiming to be FITS).
Wire-level check is JSON-Content-Type for metadata endpoints + Content-Type + magic-byte sniff
for image endpoints.

**Enforced for:** AuditService (R6.98-B) + ImageCutoutDataSet (R6.98-B).

### R6.98-C — Streaming cap MANDATORY for large responses

Large responses (>1 MiB threshold) MUST use streaming pattern with byte counter to prevent OOM.
Counterpart to R6.96-O6 (inbound pre-fetch guard). Backstop in addition to Content-Length
pre-check (which only catches compliant servers).

**Enforced for:** PipelineProxyController (R6.98-C).

### R6.98-D — DNS pinning MANDATORY for outbound to mutable-DNS third parties

Outbound HTTP to mutable-DNS targets MUST pin resolved IP at validation time via Apache
HttpClient `DnsResolver` override. Counterpart to R6.96-O7 (inbound DNS rebinding defense).

Pinning mechanism: custom `DnsResolver` resolves the target host ONCE at startup (via system
DNS) and caches the result. ALL subsequent HTTP requests through this client route through the
cached IPs — preventing DNS rebinding where the resolver returns a different IP between TLS
handshake and request body transmission.

V1 marker: `R6.98-D: DNS resolver pinned for {host} -> [{ip1}, {ip2}, ...]` emitted at startup.

**Enforced for:** ImageCutoutDataSet (R6.98-D, hips.china-vo.org).

### Cross-cutting: dedicated bean > shared bean for pinned clients

Pinned `CloseableHttpClient` MUST live in a dedicated `@Bean` method on `HttpClientConfig`,
NOT be mixed into the shared client. Rationale:
- TLS pinning for api.deepseek.com must NOT bleed into other consumers (defense isolation).
- The pinned client's connection pool is logically separate from the general shared pool.
- Future per-host overrides (DNS pinning for china-vo.org, etc.) plug in here as additional
  dedicated beans without touching the shared one.

Pattern: `{service}RestClient(CloseableHttpClient httpClient, @Value(...) String pinnedCertSha256)`
returns either `RestClient` wrapping the pinned client (when SHA-256 set) or wrapping the
shared `httpClient` (when unset, with warning log).

## Behavioral changes (none for valid callers; only for adversarial inputs)

- **Valid callers:** Behavior change: zero. Existing wire-level contract preserved (URL, method,
  headers, body, response shape).
- **Adversarial inputs (china-vo.org path):**
  - Misissued cert → TLS handshake rejected (R6.98-A) → connection fails closed.
  - DNS-rebinding attack (resolver returns different IP post-handshake) → connection uses
    pinned IP only (R6.98-D) → rebinding rejected.
  - MIME confusion (HTML claiming to be FITS) → Content-Type validation rejects (R6.98-B).
  - Oversized response (>1 MiB) → streaming cap rejects (R6.98-C).
