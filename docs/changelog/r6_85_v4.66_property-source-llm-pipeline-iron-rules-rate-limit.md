## Iron rules added (R6.85-A/B/C)

### R6.85-A — RestTemplate lifecycle MANDATORY

Any controller with `RestTemplate` MUST follow R6.83 lifecycle pattern:
- `@PostConstruct init()` — configure connect/read timeouts + emit V1 marker log
- `@PreDestroy shutdown()` — emit cleanup log (HttpURLConnection auto-closes; future factory migrations need real close())
- Null-guard 503 in business methods — if init() failed, return SERVICE_UNAVAILABLE not NPE
- V1 marker log — `R6.85b: <ControllerName> RestTemplate initialized (connect=Xs, read=Ys)` for post-deploy grep verification

**Enforced for:** LlmController (R6.85b) + PipelineProxyController (R6.85b).
**HIGH-RISK candidates for R6.87+:** StaticFileController + SearchController + ImageCutoutController (audit with `grep -n "new RestTemplate()" gw-backend/.../controller/*.java`).

### R6.85-B — @PropertySource centralization

`@PropertySource` annotations MUST be declared on the `@SpringBootApplication` class (Application.java), NOT on individual `@Value` consumers. Centralizes config provenance for audit. Exception: test-specific @PropertySource in test classes OK.

R6.85a applies this rule to `version.properties` — exposes `app.version` from build artifact to Spring `Environment`. All `@Value("${app.version:unknown}")` lookups now resolve correctly.

### R6.85-C — Rate-limit exclusion REMOVALS need rationale comment

Rate-limit exclusion REMOVALS require explicit rationale comment in source. ADDITIONS don't require comment (default behavior is rate-limit).

R6.85c `WebMvcConfig.java:23` sets the pattern:
```java
// R6.85c: REMOVED excludePathPatterns("/api/health") — /api/health is now rate-limited at default bucket
```

**Future removals** must follow this pattern: short tag (R6.x c-prefix) + REMOVED keyword + brief rationale. **Future additions** (R6.86+) should NOT add a comment unless adding non-default quota (then document the bucket name).

## Lessons (R6.85)

1. **`final` field blocks Spring lifecycle** — R6.85b kept `private final RestTemplate restTemplate = new RestTemplate();` (NOT removed `final` as originally considered). Field is initialized in constructor before `@PostConstruct` runs, so `restTemplate.getRequestFactory()` works. Null-guard 503 at LlmController.java:137 + PipelineProxyController.java:174-180 is **defensive code** — unreachable in normal operation but safe if init() throws.

2. **`@PropertySource` centralization is audit-friendly** — Application.java holds config provenance; scattered `@PropertySource` per `@Value` consumer would obscure.

3. **R6.83 iron rules scale beyond HealthController** — LlmController + PipelineProxyController now share R6.83 lifecycle. Audit pattern: `grep -n "new RestTemplate()" gw-backend/.../controller/*.java` to find more candidates (StaticFileController + SearchController + ImageCutoutController remain HIGH-RISK for R6.87+).

4. **Rate-limit exclusion removal is safer than rate-limit addition** — Removal = "make default apply"; Addition = "add custom logic". Removal needs only rationale comment; Addition needs full quota + interceptor config. R6.85c applies default 120/min/IP bucket (production profile).

5. **Marker log AND-check (R6.84b list[str] API) catches missing controllers** — `z.check_marker_log(['LlmController RestTemplate initialized', 'PipelineProxyController RestTemplate initialized'])` returns True only if BOTH init logs emit. Catches partial deploy where only 1 of 2 controllers is in jar.

6. **Portable Maven not on PATH** — `mvn: command not found` error; used full path `D:\AliCPT\tools\apache-maven-3.9.9\bin\mvn.cmd` (grep'd from `build-and-deploy-jar.py:DEFAULT_MVN`).

7. **Stale jar on first build** — initial start.jar was built from STAGED Java edits in `C:\Users\28610\r684_staging\gw-backend\` but Maven reads from `D:\AliCPT\gw-backend\` which had old source. Copy staged files back BEFORE `mvn` build.
