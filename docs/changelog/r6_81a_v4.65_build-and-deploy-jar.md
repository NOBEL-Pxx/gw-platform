## Why this exists

R6.80 (commit d43fd4e) shipped 3 deliverables but the pre-flight command was:
```bash
mvn -pl start package         # ❌ STALE — reuses .m2 cached upstream JARs
mvn -pl start -am package     # ✅ CORRECT — rebuilds upstream modules
```

Without `-am`, Maven only builds the `start` module and reuses cached
`gravitationalwave-server-service-0.0.1-SNAPSHOT.jar` +
`gravitationalwave-server-web-0.0.1-SNAPSHOT.jar` from `~/.m2`. Result: JwtUtil `:?`
fail-fast + HealthController + MongoConfig were silently missing from the live jar
until `-am` was added manually.

R6.81a makes this mistake **impossible** by hard-coding `-am` as the only supported
build command, with no flag/env-var/opt-out to remove it.

## Lessons (R6.81a)

1. **`-am` should be a script-level invariant, not a shell-memory one.** Hard-coding + test guard is the only way to prevent silent regression.
2. **Triple SHA verification (local → host → container) is cheap insurance.** `docker cp` is generally reliable but not infallible.
3. **Deprecate via stub, not delete.** H3 fix stubbed old scripts (exit 64) — preserves shell history, gives clear error.
4. **Windows dev needs explicit `sync_script_path` for zkb.** On dev workstation, ZJLAB_* env vars are typically unset.
5. **60s timeout is too tight for Spring Boot cold start on zjlab.** MongoDB retry + connection pool init + Tomcat warm-up routinely takes 60-120s.
